# Experimental full-block integer Q8 vector pipeline

Source-only physical candidate on60bcd, using the existing explicit q8_0_dot_x4 operation, exact prepared Q8_0 constant and canonical quantize_q8_1_x4 arena. No public graph API/book/default/state/cache/sampler changes, no common C++ edits and no target run. Native integration is deferred to its owner and root priority after actual incumbentQ8 compiler statistics.

## Mechanism

The incumbentWG16/ROW2 orROW4 assigns eightK values to each lane, leaving four scaled floating partials per32-value quantization block. The candidate instead assigns one complete32-value block to each lane of a16-lane subgroup. Eight signed packedDOT4 values accumulate into one exact int32 blocksum, then oneFP32 scale pair is applied and subgroupAdd combines block results. Bound32*128*128=524288 precludes int32 overflow. K384 uses12active/16lanes,12scaled block values versus48; integer dot count remains96/output. K32..512 is a generic physical bound, not a model identity.

The final frozen geometry isWG64, four independent subgroup16 rows, one output per subgroup. This preserves041's four outputs/workgroup and roughly its workgroup count; the first source draft wasWG16/one row and was revised before any immutable submission. No shared variable or workgroup barrier exists; tail row returns are uniform within their subgroup. The new path loses activation reuse across rows, has inactive block lanes and longer integer dependency chains; saved control/scales/packing may not offset them. No performance/throughput/spill claim.

Weight format remains34bytes/block (FP16 scale +32signed bytes), activation format remains144bytes/fourblocks (fourFP16 scale/sum pairs +32packedI32words). New scalaruint reads reconstruct 4bytes at offset2mod4 from adjacent words, then use signed packedDOT. Because existing exactI32 storage requires totalQ8blocks even, any evenblock's cross-word load has a following block; final oddblock quant words align4. Every read stays inside exact descriptor extent, without robustness/wholearena assumptions. Half scales use standard unpackHalf2x16, so no16-bit storage loads or shaderFloat16 arithmetic are introduced. No dequantized operand buffer is created.
